# M3.9 credential-safe manual smoke

Enter the Anthropic credential **only** in the CoderXP workspace BYOK field. That field is masked. Never place a real key in a shell command, `.env` file, source file, chat message, screenshot, test fixture, or issue report.

If a check fails, describe the UI symptom only. Do not include the key, headers, or request dumps.

## Setup

1. Start the self-hosted app with `npm run dev` or the production `npm run start` path from `docs/self-host.md`.
2. Open `/workspace`.
3. Click **Set API Key**.
4. Paste the key into the masked field and save. Confirm the UI shows **BYOK Active** and does not display the key value.

## Happy path

1. Submit a text-only prompt (no file or command request).
2. Confirm assistant text streams into the transcript.
3. Ask the agent to perform a **safe** operation that requires approval in Ask mode (for example, create a new harmless file).
4. Confirm an approval card appears. Confirm the card does not show the API key.
5. Approve the card.
6. Confirm the tool runs through the permission and execution layers.
7. Confirm a safe tool result is returned to the model.
8. Confirm a final assistant response is streamed.

## Cancel, retry, and clear

1. Start another prompt and click cancel while it is streaming. Confirm the turn stops and the transcript does not show the key.
2. Retry a prompt. Confirm a new turn starts.
3. Click **Clear Key**.
4. Submit another prompt. Confirm the provider request is blocked until a key is supplied again.

## Secret-safety checks

- The key is not shown in the transcript.
- The key is not written into project files.
- The key is not visible in the workspace terminal.
- Refreshing or closing the page clears the key. After refresh, provider requests are blocked until the key is entered again in the UI.
- Provider failures show generic internal errors, not raw upstream payloads or credentials.

Do not capture screenshots of the BYOK field, browser devtools, network headers, or terminal output while a key is present.
